## 9. v1.1.0 以太网与托盘增量验证

- 构建：0 警告、0 错误；测试：116 通过。
- 真实只读验证：通过临时 SYSTEM 任务运行 `WindowsEthernetController.Inspect()`，Windows NetAdapter 返回一块物理以太网 `Realtek PCIe GBE Family Controller`，MAC `34-97-F6-A1-BA-FE`，`AdminEnabled=True`。这说明提升上下文中的 PowerShell/NetAdapter 查询链路可用。
- 适配器枚举过滤：UI 的非提升枚举已排除同名的 QoS/WFP/Native MAC 过滤虚拟接口；禁用确认框只显示一块物理“以太网”。
- 状态机验证：4 个 fake-controller 测试覆盖禁用成功、恢复成功、无适配器 no-op、控制器失败后不留下禁用记录、无记录恢复不触碰适配器。
- 托盘验证：运行时关闭主窗口后进程仍存活、主窗口句柄为 0，日志记录“关闭窗口已转为系统托盘运行”；托盘图标创建日志正常。
- **没有执行真实网卡断开/恢复**：当前测试机只有一块正在承载当前会话的以太网。断开它会中断自动化会话，也无法在远端恢复，因此没有拿它做破坏性测试。真实硬件禁用/恢复需要用户在本机确认后执行；失败时界面会记录实际结果。
- 托盘菜单的所有交互（双击显示、托盘退出对话框、托盘启动恢复）没有全部自动化；代码路径已构建，关闭到托盘和状态持久化已验证。
- 以太网禁用状态没有自动恢复机制；程序被强制结束、系统重启或用户选择“保持断网退出”时，需要重新打开程序或使用 Windows 网络连接手动启用。这是有意设计，已在 README 明确。


## 8. v1.0.1 增量验证

v1.0.1 针对“界面以管理员身份运行后仍提示没有得到管理员权限”的问题做了两项修改：

- 管理员判定改为读取当前进程令牌的 `TokenElevation`，而不是仅检查 `WindowsPrincipal.IsInRole(Administrator)`；被 UAC 过滤的普通令牌不会被误判为已提升。
- 已提权桌面界面直接在自身进程内调用同一个 `HelperHost`/`NetworkControlService`，不再启动第二个辅助进程，也不再依赖第二次 UAC。

本次验证通过嵌套的高权限 PowerShell 启动了 Release 版 apphost：

- 启动日志为 `管理员权限=True`。
- 通过 UI 提交网络目标操作后，日志明确出现“当前桌面窗口已具有管理员权限，直接在进程内执行操作，不再请求第二次 UAC”。
- 该验证沙箱仍然拒绝自定义 apphost 的防火墙 COM（提示“当前权限无法读取 Windows 防火墙状态”），因此没有在此沙箱内完成“已提权 UI 直接创建真实防火墙规则”的最终写入验证；真实防火墙创建/删除见第 2 节，由独立提权验证控制台完成。
- 交互式 UAC 同意提示仍未验证。v1.0.1 的正常权限路径仍会启动标准 `runas` 辅助进程。

如果用户按“以管理员身份运行”启动后，界面仍显示“普通权限”，说明 Windows 没有提升该进程；本工具不能也不应该绕过系统权限。需要检查 UAC、组策略或安全软件。
